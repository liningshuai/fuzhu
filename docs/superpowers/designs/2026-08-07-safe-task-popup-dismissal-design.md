# 安全跳过任务/引导弹窗设计

## 背景

稳定性验收时，测试号进入主城后出现“官员”任务提示弹窗。该弹窗会遮挡主城，但不需要确认购买、登录或执行业务操作；用户确认它与限时活动弹窗一样，点击安全空白处即可关闭。

当前通用弹窗处理只覆盖“确定”类窗口和已知高亮弹窗，因此任务流程会在弹窗存在时继续尝试点击“更多”等坐标，最后进入下一轮重试。

## 目标

在启动流程和每轮任务开始前，安全识别这类任务/引导遮挡层，点击固定安全点 `(30, 500)`，重新截图确认遮挡层已消失，再继续主城或任务流程。

## 处理边界

需要处理：

- 当前测试号出现的“官员”任务提示弹窗。
- 与该弹窗视觉结构一致、可安全跳过的后续任务引导弹窗。
- 弹窗关闭后重新确认主城，不在旧截图上继续操作。

必须排除：

- 重复登录弹窗：交给会话恢复逻辑。
- 见证传奇、过关斩将等购买确认弹窗：交给对应业务逻辑。
- 已知“确定”类公告/系统弹窗：继续使用现有确定按钮处理。
- 无法确认类型的未知遮挡：不盲目点击，保留失败状态和日志。

## 方案

新增安全跳过弹窗识别层，优先使用专用模板识别当前“官员”弹窗；如后续采集到同类且结构稳定的弹窗，再逐个加入模板，不用单一低阈值模板覆盖所有窗口。

处理顺序为：

1. 检查业务阻塞弹窗和重复登录弹窗。
2. 检查已有的“确定”类弹窗和高亮弹窗。
3. 检查安全跳过任务/引导弹窗。
4. 命中安全跳过弹窗后点击 `(30, 500)`。
5. 重新截图；若仍被同类弹窗遮挡，按上限重复处理。
6. 只有确认回到主城或进入可识别任务页面后，才允许继续业务点击。

该识别层同时供启动流程和任务开始前的公共清理使用，避免只在启动阶段有效。

## 测试设计

新增截图回放和行为测试：

- 当前“官员”弹窗命中后只点击 `(30, 500)`。
- 点击后重新截图，并在弹窗消失后继续识别主城。
- 购买确认、重复登录和未知画面不触发空白点击。
- 连续出现多张安全跳过弹窗时逐张处理，并受最大次数限制。
- 自动领邮件在该弹窗存在时，先完成公共清理，再进入“更多”菜单流程。

验证范围包括安全弹窗专项测试、启动/导航/任务回归测试、全量测试和编译检查；不修改 `config/runtime.yaml`，不自动启用其他业务任务。

## 完成标准

- 真实截图回放能识别当前弹窗并产生唯一安全点击。
- 真实设备上该弹窗关闭后能回到主城，自动领邮件不再在遮挡层上重复点击。
- 现有购买、重复登录和未知画面保护测试全部通过。
- 8787 服务重新加载新代码后保持未挂机，等待下一次人工实测。
