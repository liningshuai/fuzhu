# 限时活动弹窗安全关闭设计

## 1. 背景与问题

启动后进入主城流程目前可以处理公告、进入游戏、永久卡奖励和已知高亮弹窗。但游戏会周期性出现充值/限时活动宣传弹窗，弹窗通常覆盖主城，且同一活动可能连续出现多张页面。该类弹窗没有稳定的关闭按钮，用户确认点击空白区域即可跳过。

如果为每一张活动海报都编写固定坐标或专用分支，活动更新后维护成本会持续增加；如果对所有未知画面直接点击空白，又可能误关购买确认、重复登录或其他业务弹窗。

## 2. 目标与非目标

### 目标

- 在启动收敛到主城期间识别并关闭限时活动弹窗。
- 先复用可维护的专用模板，覆盖已采集的活动页面。
- 对未采集但结构相似的活动弹窗提供保守的泛化识别。
- 同一活动连续出现多张弹窗时，逐张重新截图、确认后再点击。
- 已知购买、重复登录、系统确认等业务弹窗优先级高于泛化活动识别，禁止误点。
- 识别不确定时不点击，并在达到上限后以明确错误结束启动流程。

### 非目标

- 不自动点击活动弹窗内的充值、领取或购买按钮。
- 不修改见证传奇、名士拜访、过关斩将及其他业务任务逻辑。
- 不尝试识别所有游戏弹窗；泛化规则只服务于“主城被活动宣传面板遮挡”的启动场景。

## 3. 推荐方案

采用“两层识别 + 有限循环”的结构：

1. 已知模板层：识别 `startup_activity_*.png` 活动模板，模板命中后直接点击安全空白点。
2. 泛化结构层：只有在主城底图锚点仍可低阈值识别、画面存在明显全屏变暗、中央区域存在大面积活动面板，并且没有已知业务弹窗标志时，才判定为未知活动弹窗。该低阈值锚点只用于判断“主城在弹窗下面”，不能直接结束启动流程。
3. 每次关闭动作后重新截图；最多关闭 `max_activity_dismissals` 张，默认 8 张。超过上限不再点击，流程进入超时/失败路径。

泛化层采用多个条件同时满足的保守策略，不以单一亮度或单一矩形特征触发。无法形成足够置信度时保持等待，避免把未知界面当成活动弹窗处理。

## 4. 组件设计

### 4.1 `ActivityPopupDetector`

新增独立检测器，输入当前截图和模板匹配器，输出活动弹窗匹配结果或空值：

```python
class ActivityPopupDetector:
    def detect(self, screen: Any) -> ActivityPopupMatch | None:
        ...
```

`ActivityPopupMatch` 至少包含识别来源（专用模板/泛化结构）、置信度和可读原因，供日志和测试使用。检测器不执行点击，点击责任仍由 `GameStartupFlow` 统一管理。

专用模板通过 `startup_activity_*.png` 命名约定自动发现，新增活动模板不需要修改 Python 分支。模板只用于识别活动面板主体的稳定区域，避免包含活动数字、红点和易变奖励内容。

### 4.2 泛化识别条件

泛化识别至少检查以下信号：

- 主城底图锚点仍存在，例如使用放宽阈值的底栏 `nav_fief` 或其他稳定主城锚点；
- 主城关键区域相对正常主城画面呈现明显变暗，表明存在遮罩层；
- 中央活动 ROI 存在大面积、近似矩形的高对比面板；
- 购买次数、重复登录、系统确认、公告、永久卡等已知弹窗均未命中。

第一版泛化检测的中央活动 ROI 固定为 `(x=20, y=400, w=1040, h=1250)`，阈值集中在检测器中，并通过固定回放截图校准。检测器缺少必要图像输入或计算失败时返回空值，不执行兜底点击。

### 4.3 `GameStartupFlow` 集成

每轮截图的处理顺序为：

1. 公告“朕已阅”；
2. “进入游戏”；
3. 永久卡“立即领取”；
4. 已知高亮提示；
5. 已知活动模板或泛化活动弹窗；
6. `nav_fief` 主城确认；
7. 等待下一轮。

活动识别命中后只点击现有安全空白点 `(30, 500)`，计数加一并立即重新截图。活动计数达到上限时不再盲点，抛出带有计数和最后识别原因的启动异常。

## 5. 业务弹窗隔离

泛化活动识别必须位于已知业务弹窗判断之后。至少排除：

- 重复登录提示；
- 购买次数/购买确认弹窗；
- 系统公告和“确定”弹窗；
- 见证传奇、过关斩将等任务内的购买或奖励弹窗。

这些弹窗继续由已有专用流程负责。活动泛化检测只在启动收敛阶段启用，不加入通用业务导航的盲点分支。

## 6. 测试策略

### 单元测试

- 专用活动模板命中后点击安全空白；
- 泛化条件全部满足时才返回活动匹配；
- 缺少任一关键条件时不点击；
- 购买确认、重复登录和系统确认画面不会被泛化识别为活动；
- 连续两张活动弹窗按“截图 → 点击 → 截图 → 点击”顺序处理；
- 达到最大活动弹窗数量后停止继续点击并返回明确失败。

### 资产回放测试

- 使用当前用户截图作为固定活动回放样本；
- 后续可追加不同活动的回放截图和 `startup_activity_*.png` 模板；
- 现有启动、主城和购买弹窗负例测试继续通过。

## 7. 风险与降级策略

- 新活动视觉结构差异过大时，泛化检测可能无法命中；此时记录未知启动画面，并通过追加 `startup_activity_*.png` 模板补齐，不引入盲点。
- 泛化阈值过低会增加误点风险，因此默认宁可等待超时，也不对低置信度画面点击。
- 活动连续页数量超过默认 8 张时，流程停止并报告上限，避免无限点击循环。
