# 三类命令弹窗安全跳过设计

## 背景

稳定性验收过程中发现，进入主城后可能出现“建设令”“进攻令”或“防守令”发布弹窗。弹窗会遮挡主城，但用户不需要阅读发布者、命令内容或执行弹窗内业务，只需要点击空白处跳过，继续后续任务。

当前公共安全弹窗清理已经支持已知活动模板和泛化活动结构识别，但泛化结构只检查中央面板。命令弹窗的主体位于画面下半部，左侧有角色插画，右侧有金色命令信息横幅，因此现有中央面板条件可能漏检。

## 目标与边界

目标：

1. 将建设令、进攻令、防守令统一识别为可安全跳过弹窗。
2. 命中后只点击固定安全空白点 `(30, 500)`。
3. 每次点击后重新截图，支持连续出现多张命令/活动弹窗。
4. 保留现有业务弹窗保护：购买、重复登录、系统确认或无法确认的画面不得触发空白点击。
5. 继续复用启动流程和任务前公共清理边界，不新增独立任务状态。

不包含：

- 不使用 OCR 读取命令类型、发布者或命令内容。
- 不点击命令弹窗内的领取、充值、确认或其他业务按钮。
- 不修改每日任务完成记录、购买次数策略或任务配置。
- 不自动启动挂机，不修改 `config/runtime.yaml`。

## 方案

在 `ActivityPopupDetector` 中增加命令弹窗结构识别，处理顺序保持不变：

1. 先检查 `BLOCKER_TEMPLATES`。返回 `True` 或无法安全检查时立即停止，不允许空白点击。
2. 检查现有 `startup_activity_*.png` 专用模板。
3. 检查命令弹窗结构签名。
4. 最后使用现有中央活动面板泛化识别。

命令结构签名由以下条件共同组成：

- `nav_fief` 以现有主城阈值识别到，证明弹窗下方仍是主城。
- 画面边缘区域明显变暗，复用现有 `_measure_dimming`，避免把普通主城当作弹窗。
- 命令区域 `(0, 1050, 1080, 550)` 内存在足够比例的金色/橙色像素。
- 金色像素形成横向面板，而不是零散 HUD 图标：最大连通区域宽度、面积和横向覆盖率必须达到下限。
- 左下侧 `(0, 1050, 250, 550)` 存在角色插画的亮度与纹理证据，避免仅凭普通金橙色地图/HUD 区域误判。

该签名不区分三种命令类型；三种类型共享同一套视觉结构，命中结果统一返回 `source="command_order"`。以后若收集到稳定的 1080×1920 回放，可新增 `startup_command_order_build.png`、`startup_command_order_attack.png`、`startup_command_order_defense.png` 模板作为更高优先级识别，不需要修改点击流程。

## 公共流程接入

`dismiss_activity_popups()` 已经负责：

- 每轮重新截图；
- 命中后只点击 `HIGHLIGHT_CLOSE_POINT`；
- 按 `max_rounds` 限制连续处理次数。

因此不新增新的点击函数。`dismiss_confirm_dialogs()` 继续在购买弹窗保护之后调用它；启动流程继续通过同一个 `ActivityPopupDetector` 处理命令弹窗。

## 失败安全

- 模板目录缺失、图像格式错误、主城锚点识别失败、颜色结构不满足阈值时返回 `None`，不点击。
- 业务阻断检测异常时保持失败关闭。
- 结构签名只作为安全弹窗正向证据，不能覆盖购买/重复登录/系统确认保护。
- 连续弹窗超过上限时保留当前画面并由上层超时/失败处理，不进入无限点击循环。

## 测试与验收

新增测试覆盖：

1. 三类命令的共享结构签名可识别。
2. 明亮主城、无金色横幅或没有主城锚点时不识别。
3. 购买/重复登录阻断优先，命令结构存在时也不空白点击。
4. 公共清理对连续命令弹窗逐张处理，并受最大次数限制。
5. 现有活动、启动、导航和业务任务回归不受影响。

验证命令：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q src tests
Invoke-WebRequest http://127.0.0.1:8787/ -UseBasicParsing
```
