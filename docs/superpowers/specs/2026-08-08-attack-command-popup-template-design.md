# 进攻令弹窗专用模板设计

## 目标

为“攻城令发布”弹窗增加与建设令、防守令一致的专用模板识别。命中后只执行安全空白点击 `(30, 500)`，跳过弹窗并继续任务；不识别发布者、不点击“前往”、不使用 OCR，也不降低现有通用结构阈值。

## 方案

在现有 `ActivityPopupDetector` 中增加 `startup_command_order_attack` 专用模板。检测顺序保持为：业务阻断检查 → 防守令专用模板 → 进攻令专用模板 → 活动模板 → 三类命令令通用结构识别 → 通用弹窗识别。进攻令模板只裁剪标题和上方命令面板的稳定区域，排除发布者、动态数字以及右侧“前往”按钮。

专用模板未命中时，现有 `command_order` 结构识别继续作为兜底，因此不会改变建设令和防守令原有行为。清理流程不新增点击分支，仍由 `dismiss_activity_popups()` 在有界循环内逐张截图、识别后点击 `(30, 500)` 并刷新截图。

## 资产与测试

- 回放图：`assets/screenshots/startup_command_order_attack_replay.png`，标准尺寸 `1080x1920`。
- 模板：`assets/templates/startup_command_order_attack.png`，固定裁剪 `x=480, y=1330, width=360, height=180`，与防守令保持相同几何契约。
- 测试覆盖模板可读、回放命中、发布者区域变化仍命中、业务阻断优先、清理时只点击安全空白、结构兜底及全量回归。

## 验收标准

1. 进攻令回放能以高阈值命中专用模板，并返回 `source="command_order_attack_template"`。
2. 命中后设备点击记录中只能出现 `(30, 500)`，不能出现“前往”按钮坐标。
3. 业务购买、重复登录和确认弹窗优先级不受影响。
4. 现有建设令、防守令、启动流程和全量测试继续通过。
