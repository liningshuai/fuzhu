# 游戏启动与回主城状态收敛设计

## 1. 背景与目标

当前自动恢复逻辑已经能够识别“重复登录账号，请重新登录游戏”，但重启游戏后可能停留在公告页、登录页或奖励弹窗，不能直接假设游戏已经回到主城。

本功能建立统一的“启动后进入主城”状态收敛流程，供两条路径复用：

1. 用户点击 8787 面板的“挂机”时，游戏未启动或未在主城。
2. 检测到重复登录后，自动重启游戏并抢回控制权。

成功条件是识别到主城底栏的 `nav_fief`。未完成状态收敛前，不进入任何业务任务。

## 2. 状态与处理顺序

流程按每次截图重新判断，优先处理遮挡层，再判断主城：

| 状态 | 识别内容 | 动作 | 下一步 |
|---|---|---|---|
| 公告页 | “朕已阅” | 点击模板中心 | 等待登录页或主城 |
| 登录页 | “进入游戏” | 点击模板中心 | 等待加载 |
| 永久卡奖励 | “立即领取” | 点击模板中心 | 等待主城或其他弹窗 |
| 高亮剧情/势力/奖励弹窗 | “点击任意区域关闭”提示模板 | 点击已知安全空白点 | 等待主城或其他弹窗 |
| 主城 | `nav_fief` | 不点击 | 流程成功 |
| 未知加载状态 | 未命中任何模板 | 等待下一轮截图 | 直到超时 |

高亮弹窗采用通用“点击任意区域关闭”提示文字作为识别依据，不绑定“魏帝”等具体文案。只有确认提示模板命中后才点击空白区域，禁止在未知画面上盲点。

## 3. 组件设计

### 3.1 `GameStartupFlow`

新增 `src/session/startup.py`，只负责把当前游戏画面收敛到主城，不负责任何业务任务。

启动页模板使用固定全屏 ROI `STARTUP_REGION = (0, 0, 1080, 1920)`；高亮关闭提示仍在该 ROI 内识别，只有命中后才使用安全空白点。

接口：

```python
class GameStartupTimeout(RuntimeError):
    """在限定时间内未能进入主城。"""


class GameStartupFlow:
    def __init__(
        self,
        device,
        matcher,
        *,
        timeout_seconds: float = 60.0,
        poll_interval: float = 1.0,
        sleep_fn=time.sleep,
        monotonic_fn=time.monotonic,
    ) -> None: ...

    def wait_until_main_city(self) -> None: ...
```

识别和点击均使用模板匹配结果的中心点。高亮弹窗使用现有导航安全空白点中的第一个点；如果模板未命中，则不触发点击。每轮最多处理一个识别到的状态，处理后重新截图，避免一张旧截图连续点击多个位置。

### 3.2 会话恢复复用

`GameSessionGuard` 保留重复登录识别、限频和异常语义，但把“启动后等待前台及主城”的重复实现委托给 `GameStartupFlow`。这样公告、登录、奖励和高亮弹窗在普通启动与顶号恢复时保持一致。

### 3.3 BotEngine 启动复用

`BotEngine.start(ensure_game=True)` 的行为调整为：

1. 刷新设备并按现有逻辑启动游戏（必要时）。
2. 调用 `GameStartupFlow.wait_until_main_city()`。
3. 只有流程成功后才启动挂机线程。

启动失败或超时时直接返回错误，不执行业务任务。现有任务遍历顺序和任务内部逻辑保持不变。

### 3.4 通用高亮弹窗清理

将“点击任意区域关闭”识别加入现有通用弹窗清理入口，使任务运行中再次出现同类高亮弹窗时也能安全关闭。该入口只在提示模板命中时点击，不改变邮件、购买次数等现有特殊弹窗分支。

## 4. 模板资产

从用户提供的四张截图中裁剪固定 1080×1920 游戏视口内的稳定区域：

- `startup_announcement_claim.png`：公告页“朕已阅”。
- `startup_enter_game.png`：登录页“进入游戏”。
- `startup_permanent_claim.png`：永久卡奖励“立即领取”。
- `startup_highlight_close_hint.png`：高亮弹窗“点击任意区域关闭”。
- `startup_highlight_close_hint_reward.png`：奖励弹窗中的高亮“点击任意区域关闭”提示；与普通高亮弹窗分开匹配。

模板不包含雷电模拟器右侧工具栏和顶部窗口栏。模板匹配使用受限 ROI 和 0.78 左右的初始阈值，具体阈值以固定回放截图的稳定匹配分数为准。`nav_fief.png` 继续作为主城成功标志。

## 5. 异常与安全边界

- 启动流程默认最多运行 60 秒，超时抛出 `GameStartupTimeout`。
- 启动流程每轮只执行一个明确动作，动作后等待并重新截图。
- 未识别到公告、登录、奖励或高亮弹窗时不点击任何坐标。
- 高亮弹窗关闭使用安全空白点；不点击弹窗主体、奖励图标或业务按钮。
- “进入游戏”和“立即领取”只在对应模板命中时点击。
- 启动/恢复失败不进入业务任务；恢复失败仍由现有会话保护逻辑决定是否停止挂机。
- 不修改见证传奇、名士拜访、过关斩将的业务状态和流程。

## 6. 测试与验收

离线测试覆盖：

- 已在主城时不点击，立即成功。
- 公告页 → “朕已阅” → 登录页 → “进入游戏” → 主城。
- 永久卡奖励 → “立即领取” → 主城。
- 高亮弹窗 → 识别提示 → 点击空白 → 主城。
- 多种弹窗连续出现时按顺序逐个处理。
- 未识别画面不产生点击，超时返回明确错误。
- `GameSessionGuard` 和 `BotEngine` 复用该流程后，恢复仍只重试当前任务。

8787 验收：

1. 用户保持雷电模拟器在主页，不手动启动游戏。
2. 启动 8787 服务并点击“挂机”。
3. 验证自动启动游戏、处理公告、进入游戏、领取永久卡、关闭高亮弹窗并进入主城。
4. 任务开关保持用户原配置，挂机结束后检查无无关任务被执行。
