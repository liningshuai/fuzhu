# 防守令弹窗专用模板增强设计

## 1. 背景

进入主城后，游戏可能出现“建设令”“进攻令”或“防守令”发布弹窗。三类弹窗都不需要执行弹窗内业务，只需点击安全空白处跳过，继续后续任务。

当前代码已经通过主城锚点、画面变暗、左侧角色插画和底部金色横幅的结构特征统一识别三类命令。用户提供的防守令截图经过标准化回放后可以命中 `command_order`，置信度约为 `0.76`，但相对于现有阈值的安全余量较小。

本次增强只提高防守令的识别稳定性，不改变三类命令的业务行为。

## 2. 目标

1. 为防守令增加专用图像模板识别路径。
2. 专用模板优先于通用结构识别，但不能绕过业务弹窗保护。
3. 继续使用固定安全空白点 `(30, 500)`，不点击“前往”按钮。
4. 不使用 OCR，不降低现有通用结构阈值。
5. 专用模板未命中时，保留现有三类命令结构识别作为兜底。
6. 连续出现多张弹窗时，继续按现有 `max_rounds` 逐张截图、逐张处理。

## 3. 非目标

- 不识别发布者姓名、官职或命令具体内容。
- 不点击“前往”、领取、确认或其他弹窗内业务按钮。
- 不新增独立任务，不修改每日完成记录和购买次数逻辑。
- 不修改建设令、进攻令的现有识别阈值。
- 不自动启动挂机，不自动修改 `config/runtime.yaml`。

## 4. 方案选择

采用“防守令专用模板优先 + 三类命令结构识别兜底”。

相比只使用结构识别，该方案能利用防守令固定标题和面板视觉特征，提高当前截图这类画面的命中余量；相比三类命令全部改为专用模板，该方案只增加当前已观察到稳定样本的模板，维护范围更小，并保留对不同角色插画和发布者变化的泛化能力。

## 5. 模板资产规范

新增模板文件：

```text
assets/templates/startup_command_order_defense.png
```

模板从用户提供的防守令截图标准化到 `1080x1920` 后裁剪，裁剪区域只包含稳定的“守城令发布”标题及其上方金色命令面板结构，明确排除：

- 发布者姓名和官职；
- 动态资源数字、红点和时间信息；
- 右侧“前往”按钮；
- 模拟器边框、顶部工具栏和外部浏览器区域；
- 可能随角色或活动变化的非必要大面积插画。

模板匹配使用固定的高阈值，并限制在命令面板的已知 ROI 内。阈值以标准化用户截图的实际匹配分数为基准，必须保留正样本与相似非目标画面的安全间隔；不得通过降低通用阈值来换取命中率。

## 6. 识别与清理流程

`ActivityPopupDetector.detect()` 的顺序调整为：

1. 检查业务阻断模板。检测结果为 `True` 或无法安全检查时，立即返回 `None`，禁止空白点击。
2. 在限定 ROI 内以高阈值检查 `startup_command_order_defense` 专用模板。
3. 检查已有 `startup_activity_*.png` 活动模板。
4. 检查现有三类命令共享结构，覆盖建设令、进攻令、防守令的模板未命中情况。
5. 最后执行现有通用活动弹窗识别。

专用模板命中时返回统一的安全弹窗结果，建议使用：

```text
source = command_order_defense_template
reason = matched startup_command_order_defense template
```

`dismiss_activity_popups()` 不新增点击逻辑，继续执行：

1. 截图确认；
2. 命中后只点击 `(30, 500)`；
3. 等待界面变化；
4. 重新截图确认下一张弹窗；
5. 达到 `max_rounds` 后停止继续点击并保留当前画面。

## 7. 测试设计

新增或扩展回放测试，至少覆盖：

1. 用户防守令截图标准化后命中专用模板，并返回专用模板来源。
2. 修改发布者区域或动态信息后，专用模板仍可命中。
3. “前往”按钮存在时不执行按钮点击，只记录安全空白点击。
4. 业务购买、重复登录和系统确认弹窗优先级高于防守令模板，不能触发空白点击。
5. 清晰主城、无金色命令面板和普通金色 HUD 不命中防守令模板。
6. 建设令、进攻令仍可由现有共享结构识别。
7. 连续防守令弹窗按每张新截图处理，并受 `max_rounds` 限制。
8. 现有启动流程、公共弹窗清理和已实现任务回归测试不受影响。

## 8. 验收标准

- 防守令专用模板在用户提供的标准化截图上稳定命中。
- 防守令命中后实际动作只允许是 `(30,500)` 的安全空白点击。
- 业务阻断画面、普通主城和不确定画面均不点击。
- 现有三类命令结构识别测试继续通过。
- 全量单元测试通过，`compileall` 通过，8787 HTTP 健康检查返回 200。
- 代码更新后重启 8787 服务再进行运行时验证，避免旧进程继续使用旧模块。

## 9. 实施边界

本设计只涉及 `ActivityPopupDetector`、防守令模板资产及其回放测试。实施完成后再决定是否为建设令和进攻令补充同类专用模板；本次不提前扩大到三套模板或其他活动弹窗。
