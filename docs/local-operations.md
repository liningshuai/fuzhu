# 本机单设备安全运行手册

面向普通使用者与验收人员。只说明**当前已提交工程**能做什么、不能做什么，以及如何安全使用本地 WebUI 与 Job 诊断。

---

## 1. 项目定位与固定边界

当前工程是 **本机、单设备** 的本地控制与辅助框架，不是云端挂机平台，也不是真实游戏协议产品。

| 允许 | 不允许 |
|------|--------|
| 在本机运行 WebUI | 多账号、批量账号 |
| 绑定 **一台** 本机设备 | 云手机、远程设备、设备集群 |
| 使用 SQLite 保存本机运行数据 | 把数据库、日志、截图目录上传到公网或提交到仓库 |
| **Vision / ADB**：本机界面自动化（需设备已授权、人工登录游戏） | 把自动化测试或 mock 结果说成「真实游戏已成功」 |
| **protocol/**：**仅 mock**，不会操作游戏，也不会访问游戏服务 | 真实游戏协议连接、外网游戏 API |
| 查看 Job 状态、失败分类与安全提示 | 处理、保存或反馈真实游戏凭据（Token、Cookie、密码、会话等） |
| 本机或可信局域网内的管理访问 | 代理池、规模化 Worker、绕过检测或风控的方案 |

**请牢记：**

- 自动化测试通过、协议 mock 成功，**都不等于**真实游戏流程已在本机实机成功。
- 真机 Vision 路径必须经过 **人工、授权、本机单设备** 验收；本手册不描述游戏内具体操作步骤。
- 当前工程 **不以** 协议路线或规模化账号执行为目标。

## 2. 启动前检查

在启动服务前，请自行确认：

1. **环境**：已按项目 `README.md` 完成依赖安装（例如使用 `uv sync` / `uv sync --extra dev`）。
2. **端口**：本机 Web 服务默认端口未被其他程序占用。
3. **数据目录**：运行产生的数据库与日志属于本机数据，**禁止**提交到 Git 或随意上传给他人。
4. **访问范围**：默认应只在本机使用（监听本机回环地址）。  
   - **LAN 模式默认应关闭**。  
   - 若确需在可信局域网访问：须在配置中显式开启，并设置管理口令；浏览器侧通过请求头 **`X-Admin-Token`** 完成管理鉴权（**不要**把口令写在网址里）。
5. **配置字段名**（仅作核对用，**不要**在文档或聊天中填写真实值）：  
   - 配置文件中的 `api.allow_lan`、`api.admin_token` 等；  
   - 或环境变量名如 `FUZHU_ALLOW_LAN`、`FUZHU_ADMIN_TOKEN`（以项目 README / 配置说明为准）。  
   **禁止**把真实口令写进 README、截图、书签或共享笔记。

本阶段手册 **不** 要求你启动服务；启动命令以 `README.md` 中已有本地命令为准（如 `uv run fuzhu-api`）。

## 3. WebUI 的正常使用流程

通用顺序（与当前界面一致）：

1. 在本机启动本地服务（见 README）。
2. 用浏览器打开本地 WebUI 地址（README 中的本机地址，默认为本机回环 + 端口）。
3. 若启用了 **LAN 模式**：页面会先要求输入 **管理口令**（密码框），通过后再进入控制台。
4. 确认 **角色** 与 **设备绑定** 状态（未绑定设备时，识图类任务会被阻止）。
5. 在任务列表中打开需要的开关，或选择执行通道偏好（如识图 / 协议模拟）。
6. 使用「立即执行」或「跑已启用」提交任务。
7. 在 **「Job 历史 / 诊断」** 中查看状态、排队、失败分类与用户提示。

**关于管理口令（仅 LAN 模式）：**

- 口令只应留在 **当前浏览器标签页的运行内存** 中；
- **刷新页面** 或接口返回 **401** 后，必须 **重新输入**；
- **不要** 把口令放进网址查询参数；
- **不要** 存入浏览器 Storage、Cookie，或写进个人笔记后随处转发。

本手册 **不** 包含游戏内点击步骤、坐标、模板制作或界面识别技巧。

## 4. 执行通道与 Job 状态

### 4.1 执行通道

| 通道 | 含义 | 说明 |
|------|------|------|
| **vision（本地识图）** | 本机通过 ADB 做界面自动化 | 需要角色已绑定本机设备；游戏需已由人工登录；界面或条件不满足时可能 **失败** 或 **被阻止** |
| **protocol mock（协议模拟）** | 本地假数据联调 | **不会操作游戏**，**也不会访问游戏服务**；结果仅表示 mock 逻辑跑通 |
| **不可用** | 当前任务没有可用实现 | 请勿强行当作成功 |

### 4.2 Job 状态

| 状态 | 含义 |
|------|------|
| `queued` | 已入队，等待执行（常见于同设备前一任务仍在跑） |
| `running` | 正在执行 |
| `succeeded` | 已成功结束（对 mock 仅表示模拟成功；对 Vision 表示本地自动化判定成功） |
| `failed` | 已失败结束 |
| `blocked` | 被阻止，无法按当前条件执行（例如未绑定设备） |
| `cancelled` | 已取消（若界面未提供取消，可能较少见到） |

### 4.3 单设备队列（仅 Vision）

- 同一本机设备上，Vision 任务 **串行**：同一时刻最多 **一个** `running`。
- `queue_position = 0`：表示该 Job **正在执行**。
- `queue_position = 1, 2, …`：表示同设备 **排队快照** 中的位置（从 1 起）。
- 排队位次 **不是** 完成时间承诺，只反映「此刻队列里谁在前」。
- **非 Vision** 任务的 `queue_position` 可以为空（不适用本机识图队列）。

## 5. 失败码与用户处置

下列 `failure_code` 来自 Job 诊断字段。处置仅为安全、用户级建议。

| failure_code | 常见含义 | 你可以怎么做 |
|--------------|----------|----------------|
| `DEVICE_NOT_BOUND` | 角色未绑定本机设备 | 在控制台完成设备绑定后再试；**不要**用未授权设备 |
| `DEVICE_BUSY_OR_QUEUED` | 设备忙或任务在排队（多为 **queued** 说明，不是失败） | **等待**队列自动推进即可（同设备串行）；在 Job 历史查看 `queue_position`；**不要**重复点击或重复提交同一任务。只有该 Job 后续进入 `failed` 或 `blocked`，且 `retryable=true` 时，才可在人工确认本机条件后考虑重新提交 |
| `PRECONDITION_NOT_MET` | 开始条件不满足（例如界面不在预期状态） | 确认本机服务仍在运行、设备侧环境正常后，再 **手动重试** |
| `TARGET_NOT_FOUND` | 未找到预期目标 | 确认本机设备与游戏界面仍可用后，再手动重试；不要为此导出敏感日志 |
| `POSTCONDITION_NOT_MET` | 操作后校验未通过 | 不要把结果当成成功；记录 Job 诊断字段后手动重试或反馈维护者 |
| `EXECUTION_ERROR` | 本地执行出错 | 确认服务未异常退出后手动重试；保留安全诊断字段 |
| `RECOVERED_AFTER_RESTART` | 服务重启导致未完成任务被中断 | 服务恢复后，在控制台 **手动再次执行** 需要的任务 |

成功或尚未失败时，`failure_code` 通常为空。

**不要**为了排错而：抓取完整原始日志、导出数据库、打包截图目录、索要设备序列号、查看 Token/Cookie，或分析外网/游戏请求。

## 6. 安全诊断与反馈模板

### 允许反馈（最小信息）

向维护人员反馈时，**只**需要（可从 WebUI Job 历史复制，勿夹带口令）：

- Job ID  
- `task_key`  
- `route`（如 vision / protocol）  
- `status`  
- `failure_code`  
- `user_message`  
- `retryable`  
- `queue_position`（如有）  
- 大致发生时间  
- 访问方式：本机访问，或是否启用了 LAN 模式（**不要**写出口令本身）

### 禁止反馈 / 禁止上传

- 管理口令（`admin_token` / 浏览器里输入的口令）  
- Token、Cookie、密码、会话材料  
- 数据库文件（如 `data` 下的库文件）  
- `.env`、本地覆盖配置  
- 原始 HTTP 请求/响应  
- 截图目录、运行日志目录整包  
- 设备序列号、本机用户名、完整本机敏感路径
